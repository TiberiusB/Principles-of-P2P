This is a short bridge for P2P-ness assessments. It is not a literature review. Read it before scoring Economic 3.1–3.2 and Structural 1.4, and before writing the compilation section **Value theory and benefit redistribution**.

## What “value” means here

In Open Value Network (OVN) practice, **value is not market price**. People experience value; the network logs **contributions** (time, care, materials, money, knowledge, reputation work) and redistributes **benefits** (revenue, access to governance, use of shared resources) according to a social contract.

Sensorica now says **contribution accounting**, not “value accounting.” The older phrase **value equation** is retired in practice because it sounds like a meter of a person’s worth. The living idea is a **benefit redistribution algorithm**: a dimension-reduction operator over a **logged contribution graph**, often shown as a pie-chart (fluid equity). The algorithm is a social agreement, not a discovery of objective worth.

Allocation, on the OVN wiki, is not only “who gets what.” It is who engages where, when, how, and with what effects — a time-dependent relation, not a static assignment.

The [OVN license](https://ovn.world/index.php?title=OVN_license) attaches reciprocity to the work: a contribution pie-chart travels with forks (indicative floors: 0.5% of material benefits for non-commercial use, 2% for commercial use). That is a different instrument from a dual GNU Affero General Public License (AGPL) plus paid commercial exception, though both can implement **copyfair** reciprocity (see the [Peer Production License](https://wiki.p2pfoundation.net/Peer_Production_License)).

## Required assessor questions

Answer these in `_data.md` (3.2 / 3.2b) and the compilation Value section. Status + Confidence + citations on each.

1. **What counts as a contribution?** Code only, or time, care, documentation, materials, money, hosting, facilitation?
2. **What is logged versus merely appreciated?** Is there a graph of events (Resources, Events, Agents / ValueFlows), or only peer praise, tokens, or salary?
3. **Who may update weights?** A founder, a council, anyone in the holon / venture, or an unpublished admin?
4. **Does a pie-chart travel with forks?** If the code or design is reused, do prior contributors retain a claim?
5. **Is capital a contribution type or a governor?** Can investors or sponsors steer strategy outside the contribution log?
6. **What is excluded?** Care, coordination, translation, and maintenance are the usual under-counts. Name them if they are invisible.

Do not collapse these answers into a single “value score.” They inform existing cells. A high Economic average that hides an appreciation-only equity meter must be surfaced in the principles cross-check.

## How this differs from common lookalikes

| Pattern | What it measures | OVN note |
| ----- | ----- | ----- |
| Price / token balance | Exchange value at a moment | Necessary for market interface; not the contribution graph |
| Peer appreciation / Coordinape-style | Visibility and esteem | Useful signal; a poor sole equity meter (incumbent bias) |
| Hours only | Clock time | Misses materials, care, and quality |
| Dual license / commercial exception | Reciprocity via a second grant | Copyfair / Peer Production License family; OVN license keeps reciprocity in one public license |
| Benefit redistribution + pie-chart | Logged multi-type contributions → shares | OVN default; “value equation” if used should mean this, not a worth-meter |
