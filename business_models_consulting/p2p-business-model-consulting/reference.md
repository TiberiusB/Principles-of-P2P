## Workflow

### 1. Intake

Fill `../templates/intake.md`.

Clarify:

- organization;
- scope;
- audience;
- register;
- available evidence;
- human goals and constraints.

### 2. Evidence

Use the repository assessment workflow when possible. If no full assessment exists, use `../templates/research_log.md`.

For OVN, P2P, Sensorica, Nondominium, contribution accounting, value, benefit redistribution, or custodianship claims, query Grounded Docs before asserting facts.

### 3. Current model

Fill `../templates/current_model.md`.

Identify:

- product/service/platform/ecosystem layers;
- business-model patterns;
- monetization gates;
- governance boundaries;
- open/closed boundary;
- capture and lock-in risks.

### 4. Technical capability map

Fill `../templates/technical_capability_map.md`.

Connect features to economic possibilities. Do not claim the organization has built future capabilities; mark them as opportunities.

### 5. Opportunity map

Fill `../templates/opportunity_map.md`.

Name value layers that become visible when the technology is used by groups, networks, open ventures, or ecosystems.

### 6. Sustainability design

Fill `../templates/sustainability_models.md`.

Separate:

- service cash flow;
- ecosystem services;
- benefit redistribution.

Use OVN-compatible patterns only when they solve a visible problem.

### 7. Migration path

Fill `../templates/migration_path.md`.

Prefer staged transitions:

```text
current hybrid
-> legible service/utility boundary
-> ecosystem integration package
-> socio-economic pilots
-> utility core
-> steward circle
-> edge ventures
-> field finance
```

### 8. Founder-facing suggestions

Fill `../templates/founder_suggestions.md`.

Write as an opportunity map. Use direct, respectful language. Avoid commands unless the user explicitly asks for prescriptive recommendations.

### 9. Human supervision

Use:

- `../templates/human_supervision_log.md`
- `../templates/claims_checklist.md`

The human assessor must review the tone, major claims, recommendations, and any speculative opportunity framing.

## Case memory

Flowsta pattern:

- current service wrapper around user-owned identity/signing infrastructure;
- opportunity to become shared trust infrastructure for hApps and open ventures;
- key transition: service cash flow plus ecosystem services plus benefit redistribution.

YourOwnAI pattern:

- local-first AI and signed records;
- opportunity to evolve toward OurOwnAI and group intelligence infrastructure;
- key transition: AI app/service plus protocol utility plus edge ventures.
